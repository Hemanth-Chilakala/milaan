# Milaan

AI-assisted payment reconciliation for Indian NBFCs, powered by Exasol Personal.

Team: **The Singleton**. Solo entrant: **Hemanth Chilakala**.

## Problem statement

A reconciliation analyst at a mid-sized Indian NBFC can't close the day's books on time because UPI, NACH and payment-gateway settlement files arrive in different formats with mismatched references, so they chase breaks by hand in Excel. If this worked, they'd close the books before noon and spend their time only on the exceptions that actually matter.

## Environment

Python 3.12 and Podman are required. The devcontainer requests at least four CPU
cores, 16 GB RAM and 32 GB storage. Eight cores and 32 GB RAM are recommended for
the planned 10-million-record benchmark.

Open the project folder as the workspace when using its devcontainer. Creating a
devcontainer file in a subfolder does not rebuild the existing parent Codespace.

After accepting the [Exasol Personal EULA](https://www.exasol.com/terms-and-conditions/#h-exasol-personal-end-user-license-agreement):

```bash
bash .devcontainer/post-create.sh
source .venv/bin/activate
bash scripts/exasol-local.sh install local --auto-approve
bash scripts/exasol-local.sh slc install python3 --auto-approve
bash scripts/exasol-local.sh connect -f sql/00_feasibility.sql
sudo .venv/bin/python scripts/check_environment.py --write-env
```

The post-create script installs dependencies and the launcher; database
deployment and EULA acceptance remain separate, explicit steps.

The verified deployment uses rootful Podman through the wrapper above. It
requires passwordless sudo in the devcontainer. Rootless Python runtime mounts
failed on the measured host. The wrapper places Podman storage in
`private/podman-storage` on the workspace filesystem and uses crun with netavark.
The application will read the generated, git-ignored
`.env`, whose permissions limit access to its owner. The environment check
verifies a TLS certificate fingerprint over the loopback connection.

Manage this deployment with `bash scripts/exasol-local.sh info`, `start` or
`stop`. Use the wrapper consistently; an unqualified `exasol start` selects a
different deployment and Podman user.

See [environment verification](docs/environment.md) for the measured setup
status and any outstanding limitations.

## Data and explanations

All data is synthetic, generated by `generator/`. No real customer, bank or
employer data is used. The generator is planned for Phase 1.

The product will run without an AI API key. Evidence-based explanations will
be deterministic. AI narration is planned for the demonstration video.
